# jmp-in-telegram

[English](README.md) | **Русский**

Телеграм-бот, через который можно пользоваться [JMP.chat](https://jmp.chat): у человека в телеге панель с его номерами и входящими SMS (коды подсвечиваются, есть кнопка «скопировать»), из бота можно и отправить SMS, посмотреть баланс, пополнить его и получить напоминание о продлении номера.

Работа с JMP вынесена в отдельную библиотеку [`jmp-chat`](https://github.com/justkiddingxd/jmp-chat) ([npm](https://www.npmjs.com/package/jmp-chat)).

## Как это устроено

```
Telegram ── бот (puregram) ── XMPP-клиент на каждый номер ── наш ejabberd ══ s2s ══ cheogram.com (JMP)
```

1. «Получить номер» → бот через HTTP API ejabberd создаёт джаббер-аккаунт `tg<id>-xxxxxx@XMPP_DOMAIN`.
2. Бот логинится в этот аккаунт и запускает ad-hoc команду `jabber:iq:register` на `cheogram.com`. Это стандартная регистрация в JMP:
   - поиск номера: человек вводит код региона или жмёт «Показать любые»;
   - выбор номера из списка (кнопки в телеге);
   - fair use policy: бот проходит его сам;
   - активация: бот спрашивает свой промокод или инвайт-код JMP. Человек может прислать его или нажать «Без своего кода», тогда бот подставит **наш промокод `JMP_PROMO_CODE`**. Если JMP не принял код человека, бот спросит снова и объяснит причину. `activation_method=code` и валюту `JMP_CURRENCY` бот ставит сам.
3. Когда номер готов, SMS приходят на джаббер от `+1XXXXXXXXXX@cheogram.com`, и бот пересылает их в телегу.

Шаги, которые бот не знает (если JMP поменяет формы), показываются человеку как есть: кнопками или запросом текста. Поэтому регистрация не сломается молча.

Если человек бросил регистрацию на середине, в меню появится «Дооформить номер». Используется тот же джаббер, и JMP помнит выбранный на нём номер.

## Свои джабберы

К боту можно привязать уже существующий джаббер на любом сервере, например с уже оформленным номером JMP:

- в боте кнопка «Подключить свой джаббер» (на главной или в карточке номера): бот спросит JID и пароль, сообщение с паролем сразу удалит;
- или командой `/import jid пароль` (сообщение тоже удаляется);
- из консоли (бот перезапустить после):
  ```bash
  docker compose run --rm bot node --import tsx src/cli/import.ts <tg_id> <jid> <пароль>
  ```

Бот проверяет пароль и спрашивает JMP, есть ли на джаббере номер. Если номера нет, джаббер привязывается, только если человек может оформить номер из бота (не упёрся в `MAX_NUMBERS_PER_USER` и нет другого недооформленного). Подключать можно только джабберы на публичных доменах (IP и внутренние имена вроде `ejabberd` отклоняются). Одному юзеру можно привязать до `MAX_IMPORTS_PER_USER` своих джабберов.

Привязанный джаббер можно отвязать кнопкой «Отвязать» в карточке номера (с подтверждением): бот отключается от него и удаляет аккаунт и историю SMS из своей базы. Сам джаббер и номер JMP остаются у человека. Аккаунты, созданные ботом на нашем сервере, так не отвязываются.

Админы не ограничены ни `MAX_NUMBERS_PER_USER`, ни `MAX_IMPORTS_PER_USER`.

## Данные джаббера

В карточке номера есть кнопка «Данные джаббера»: JID, пароль (под спойлером, с кнопками «скопировать») и сервер. С ними можно зайти в аккаунт любым XMPP-клиентом (Conversations, Monal, Gajim, Dino), для этого на сервере должен быть открыт порт 5222. SMS тогда приходят и в клиент, и в бота. `mod_register` на сервере не включён, так что сменить пароль из клиента нельзя и бот не потеряет доступ.

## Баланс и пополнение

В карточке номера видны баланс аккаунта JMP (из команды `info`) и JID, к которому привязан номер. Кнопка «Пополнить баланс» открывает экран со способами оплаты, все они идут напрямую в JMP:

- **картой**: личная ссылка на pay.jmp.chat (команда JMP `credit cards`), где можно оплатить, привязать карту и включить автопополнение;
- **с привязанной карты**: если карта уже привязана, у JMP появляется команда `top up`. Бот проводит её формы прямо в телеге и сумму всегда спрашивает у человека;
- **криптой** (Bitcoin, Bitcoin Cash, Monero, Ethereum): бот берёт адрес через команду `alt top up` и показывает его с кнопкой «скопировать».

## Промокоды

Кнопка «Промокоды» в карточке номера показывает ответ команды JMP `referral codes`: многоразовый реферальный код (другу месяц после оплаты, владельцу месяц, когда оплата друга пройдёт) и одноразовые инвайты, если они есть. Каждый код копируется кнопкой, исходный текст JMP лежит в свёрнутой цитате.

## Напоминания о продлении

Раз в час бот смотрит дату продления и баланс каждого номера. Если до продления 7, 3, 2 или 1 день, а на балансе не хватает на следующий месяц, человеку приходит напоминание: когда продление, сколько спишут и сколько не хватает, с кнопками «Пополнить баланс» и «Не напоминать».

- Хватает денег на балансе — напоминания не приходят: JMP продлит номер сам.
- Каждое напоминание приходит один раз. Если бот лежал в нужный день, он пришлёт ближайшее: например, вместо пропущенного «за 3 дня» придёт «за 2 дня».
- Выключить и включить обратно можно кнопкой «Напоминания» в карточке номера.

## Языки

Бот говорит по-русски и по-английски. Язык берётся из настроек Telegram человека: у кого Telegram на русском, тот видит русский интерфейс, остальные — английский. Язык запоминается в базе, поэтому уведомления о SMS и напоминания приходят на нём же. Для тех, чей язык бот ещё не видел, работает `DEFAULT_LANG` (`en` по умолчанию). Команды в меню Telegram тоже на двух языках.

Все тексты — в `src/i18n/ru.ts` и `src/i18n/en.ts`. Английский словарь по типу обязан совпадать с русским, так что забытая строка не соберётся.

## Кастомные эмодзи

Иконки в тексте и на кнопках — кастомные эмодзи из набора [Telegram Android Icons](https://t.me/addemoji/TgAndroidIcons). ID собраны в `src/bot/icons.ts`. Кастомные эмодзи Telegram показывает, только если у владельца бота есть Telegram Premium (или бот купил юзернейм на Fragment); иначе вместо них молча видны обычные эмодзи.

## Деплой

Нужен сервер с публичным IP и домен под джаббер (например `xmpp.example.com`).

1. DNS: A-запись `xmpp.example.com` → IP сервера.
2. Открыть порты **5269** (s2s, через него ходит cheogram.com), **80** (выпуск сертификата Let's Encrypt), 5222 (по желанию, если надо заходить в аккаунты обычным клиентом).
3. `cp .env.example .env` и заполнить `BOT_TOKEN`, `XMPP_DOMAIN`, `ACME_EMAIL`, `JMP_PROMO_CODE` и `SECRET_KEY` (`openssl rand -base64 32`). `SOURCE_URL` — ссылка «Исходный код» внизу главного меню (пустая строка убирает её), `DEFAULT_LANG` — язык по умолчанию.
4. Запуск:
   ```bash
   docker compose up -d --build
   ```
5. Проверить, что сертификат выпущен (без валидного TLS cheogram.com не станет общаться с сервером):
   ```bash
   docker compose exec ejabberd ejabberdctl list_certificates
   ```

Внутренний c2s (5223) и HTTP API (5280) ejabberd наружу не публикуются: ими пользуется только бот внутри docker-сети. Публичной регистрации на сервере нет, аккаунты создаёт только бот.

## Локальный запуск бота

```bash
npm i
npm run typecheck
npm start
```

`XMPP_DEBUG=1` выводит в консоль весь XMPP-трафик. Это нужно, если JMP поменял формы регистрации и надо посмотреть, что он присылает.

## Библиотека jmp-chat

Всё общение с JMP (SMS, ad-hoc команды, формы, номера ↔ jid шлюза, извлечение кода, баланс, пополнение, регистрация) живёт в библиотеке [`jmp-chat`](https://github.com/justkiddingxd/jmp-chat), она ставится из npm. Обновить: `npm i jmp-chat@latest`, потом пересобрать образ `docker compose up -d --build bot`.

## Структура

| файл | что делает |
|---|---|
| `src/bot/ui.ts` | экраны: главная, карточка номера, история, уведомления о SMS |
| `src/bot/panel.ts` | обработчики, флоу регистрации и отправки SMS, входящие, `/import` |
| `src/bot/prompt.ts` | вопросы человеку (кнопки/текст) в панели, листание длинных списков |
| `src/i18n/` | тексты интерфейса: `ru.ts`, `en.ts` и выбор языка по Telegram (`index.ts`) |
| `src/bot/icons.ts` | ID кастомных эмодзи, `icon()` для текста и `withIcon()` для кнопок |
| `src/bot/reminders.ts` | ежечасная проверка продления и рассылка напоминаний |
| `src/jmp/renewal.ts` | когда напоминать: пороги 7/3/2/1 день, хватает ли баланса |
| `src/jmp/info.ts` | кэш статуса аккаунта JMP (`jmp.account.info()`: активен, баланс, дата продления) |
| `src/jmp/import.ts` | привязка существующего джаббера |
| `src/jmp/topup.ts` | пополнение баланса JMP поверх `jmp.topUp`: вопросы человеку и вид результата |
| `src/jmp/register.ts` | регистрация поверх `Registration` из jmp-chat: стадии search / choose / activate → вопросы в телеге, промокод |
| `src/xmpp/account.ts` | XMPP-подключение аккаунта + `JmpClient.attach()` на нём (SMS, ad-hoc команды) |
| `src/xmpp/ejabberd.ts` | создание аккаунтов через mod_http_api |
| `src/xmpp/pool.ts` | пул подключений всех аккаунтов |
| `src/db.ts` | sqlite (`node:sqlite`): аккаунты, история SMS, отправленные напоминания, язык пользователей |
| `ejabberd/ejabberd.yml` | конфиг джаббер-сервера |

## Ограничения

- Пароли джабберов бот обязан помнить, чтобы входить в них, поэтому хранит их в sqlite **зашифрованными** (AES-256-GCM, ключ `SECRET_KEY` из `.env`). Утёкшая база или её бэкап без ключа паролей не раскрывает. Если утекут и база, и `.env` (то есть весь сервер), пароли раскрыть можно: от взлома самого сервера это не защищает. Ключ храни отдельно от бэкапов `data/`.
- ejabberd хранит пароли наших аккаунтов только как SCRAM-хеши (`auth_stored_password_types`). Если сервер поднимался со старым конфигом, остатки plain-паролей убирает `ejabberd/drop-plain-passwords.sh` (порядок — в шапке скрипта).
- В отладочный лог (`XMPP_DEBUG=1`) SASL-обмен не пишется: при PLAIN-входе там был бы пароль.
- На каждый номер держится отдельное XMPP-подключение. Несколько сотен номеров это выдержит, для тысяч нужно переделывать.
- Платные (premium) номера промокодом не активируются. Бот скажет выбрать другой номер.
